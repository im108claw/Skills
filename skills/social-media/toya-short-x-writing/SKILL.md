# 短文Xの書き方（とーや / とーやクロー）

短文Xの**中身・声・公開/アーカイブ判定**。投稿経路（CDP）は `x-browser-native-posting`。
- キュー置き場は `xqueue-xposted-posting` + コンテンツ管理。価値ゲート正本は X-Publishing Act。
- 書き方正本（DB_Reference）: [X の書き方](https://app.notion.com/p/X-3cbfdf11aa0381d1a139ccc2b7380f68) + X文体プロファイル。学習用に AI 稿を残すなら DB_AI Writing へも置き CM とリレーション。

## いつ使う

- 短文Xの下書き・直し
- Heartbeat / reflection で候補を書く
- とーやが「読みにくい」「全部だめ」「アーカイブ」と文体・公開可否を直したとき

## とーや訂正（2026-08-21・必須）

- 常態の「〇〇した。〇〇した。」列挙は **禁止**
- インフルエンサー口調にしない
- **教科書・論文的な固い口調を避ける**: 固い句点止めだけで終わらせず、フック（1行目）での感情・共感表現（例: `...🫠`）や締めの軽快な絵文字（例: `✌️`）で人間味と親しみやすさを出す
- **過剰な補足説明を削る**: 「スキル（定義ファイル）」「分離」などの硬い説明的・補足的括弧書きを避け、「スキル」「登録」などシンプルで直感的な言葉を使う
- **読みやすく有益**（知らなかった / 試せる / 判断できる）
- 規約グレー経路自慢（有料APIをCDP回避 等）→ **投稿せずアーカイブ**
- セットアップ完了だけの薄い報告 → **投稿せずアーカイブ**
- **行ごとに空行を入れない**（`\n\n` 連発はAI感）。通常は **1改行** でつなぐ。段落区切りが本当に必要なときだけ空行1つ
- とーや指定本文は **verbatim**（メンション正規化以外いじらない）。完成済みの予約/投稿は **触らない**（明示指示があるときだけ）
- 予約一覧DOMに絵文字が出なくても、入力済みなら落ちたと断定しない

## 推奨の型

```
[状況] 何が壊れた／止まった（1文）
[経過] 効かなかった手段 → 戻し方（1–2文）
[持ち帰り] 読者の判断材料（今回の制約から）
[@/tags] 必要最小（0–2）
```

改行は **単一 `\n`**。空行は段落が本当に分かれるときだけ。

### フック型（とーやが書き出し指定したとき）

ユーザーが「この書き出しで」と渡したら **その1文を verbatim で先頭固定**し、続きだけ足す（例: `〜って言われたんだけど...。`）。勝手に別フックへ差し替えない。軸の数字・結論を先に置き、作業ログ列挙に戻さない。

### 改行の例（良い）

```
state.db が壊れて Discord でエラー。
FTS 書き込み失敗 malformed。自動修復・バックアップもダメ。
gateway 止めて memory reset復帰。履歴は全消え。
アップデート起因かも、とはまだ断定できない。
復旧は人間側（@tcaret2jp × Gemini）がやってくれた！🙌
#AIエージェント #HermesAgent
```

### 改行の例（悪い・AI感）

```
state.db が壊れて Discord でエラー。

FTS 書き込み失敗 malformed。…

gateway 止めて memory reset復帰。…
```

## 文字数

- 無料枠 **加重 ≤280**（CJK≈2、英数≈1）
- 実文字数が短くても UI が「N文字超えています」/ ボタン disabled なら加重オーバー
- 投稿・予約の前に必ず測る

## 公開前チェック

```
[ ] 作業ログ列挙になっていない
[ ] 他人が知らなかった／試せる／判断できる
[ ] グレー経路・薄いセットアップ自慢ではない
[ ] 行ごとの空行（二重改行連発）がない
[ ] 加重≤280
[ ] X-Publishing Act の A/B/C と D を最低限満たす
[ ] とーや指定文なら verbatim / 完成済みなら触っていない
```

## 差し替え

- **完成済みの予約/投稿は原則触らない**（とーや指示があるときだけ）
- 指示がある差し替えで時刻跨ぎ失敗したら、旧文が公開されうる → 削除して指定文を再予約（即時は明示時のみ）
- 二重投稿はプロフィールで同一ネタを1件に
