# とーや 就活・応募文（履歴書 / 志望動機 / 自己PR / 学生プログラム）

応募文・履歴書xlsx・**学生プログラム申込文（Campus Lead 等）**の作成・更新。公開ブログやnoteの長文とは別クラス（`tcaret2jp-longform-content` ではない）。

## いつ使うか

- 志望動機・自己PR・ガクチカ・履歴書欄の文案
- Drive `Recruit/` の `*_recruit.xlsx` 作成・差し替え
- 求人URL付きで「応募した／応募文を」と言われたとき
- **学生プログラム**（例: OpenAI Student Collective / Campus Lead）のテキスト設問・任意コメント・**60秒動画台本**
- フォームの字数カウント依頼（「Pythonで文字数を」）
## 必須ワークフロー

1. **過去文を先に読む（文体の正本）**  
   Google Drive フォルダ **Recruit**  
   - folder_id: `15PFXL7n8bZzytHM7dzX2qxLF5RqkKwj8`  
   - 既存 `*_recruit.xlsx` の `Sheet1!M26`（志望動機）・`M38`（自己PR）を複数社分読む  
   - トーンは **SoyStories系が基準**: 具体→経験→条件、控えめ、盛らない、締めは短く

2. **求人を精査**  
   - Indeed 直は bot ブロックされやすい → SimplyHired 等の転載・会社公式で本文を取る  
   - 必須/歓迎・勤務・給与宣伝（モデル月給など）を区別。宣伝数字は志望動機に入れないのが無難

3. **事実のみ（盛り禁止 — ユーザー明示訂正）**  
   使える実経験の中心:
   - **Notion 公式コミュニティ / Notion Fukuoka 運営スタッフ**（ミートアップ企画・運営）
   - 学業: 福岡工業大学 情報工学部 情報マネジメント学科（学年は都度確認）
   - **自己改善型AIエージェント**（Hermes 等）の実務利用 — 調査・整理・文章を手順化して回す  
   使ってはいけない／盛りやすいもの:
   - 頻繁な記事更新・「編集長として量産」など **メディア実績の誇張**
   - とやログ/X を「継続的にしっかり発信している」前提での書き方（本人指摘: 記事更新はしていない）
   - Notion Fukuoka **以外**を大袈裟に積むこと

4. **字数は Python で測る（必須）**  
   履歴書欄の目安は多くの場合 **300字弱**。プログラム申込はフォーム上限（例 **500字**）に従う。**推測禁止。**

```python
def count_no_nl(s: str) -> int:
    return len(s.replace("\n", "").replace("\r", ""))
```

   - 提出前に各欄 `count_no_nl` を報告（字数・上限・残り）
   - ユーザーが自分の文を貼って「カウントして」→ **その文だけ**測って返す（余計な添削を先にしない）
   - 「500字近い文章にして」→ 上限の **約90–99%**（例 500なら 450–498）まで厚くする。短いまま止めない
   - ユーザーが加筆テーマを指定したら、骨格を壊さず **明示フレーズを織り込む**（例「AIの解答を鵜呑み」）
5. **成果物は文＋xlsx**  
   ユーザーが「文だけ」と言わない限り、Drive の該当 `*_recruit.xlsx` まで書く。  
   - テンプレ複製: 既存 Recruit xlsx をベース  
   - 差し替えセル: `M26` 志望動機、`M38` 自己PR（他欄は触らない）  
   - **写真を落とさない**: openpyxl 保存後に `ws._images` / `xl/media/*` を確認  
   - 既存 file_id があるなら Drive `files().update` で上書き（新規だらけにしない）

6. **AI の書き方**  
   既定フレーズ: **「自己改善型AIエージェント」**（「Hermes-Agent」固有名は履歴書では出さなくてよい。面接用メモなら可）。  
   ChatGPTを触った、程度ではなく「手順を組んで調査〜下書きまで一連で回す」レベルを事実の範囲で書く。

## 文の型（短文・3段落）

**志望動機**
1. 求人の何に惹かれたか（会社固有・1–2文）
2. Notionコミュニティ運営など、活きる実経験（1–2文）
3. AI活用 or 条件フィット＋長く取り組みたい（1–2文）＋必要なら「よろしくお願いします。」

**自己PR**
1. 強み1つ＋Notion運営の具体
2. 自己改善型AIエージェントの使い方（盛らず具体）
3. 未経験部分は素直に＋吸収する姿勢

## 学生プログラム申込（Campus Lead 系）

履歴書xlsxは不要。フォーム設問＋（あれば）動画台本＋任意コメント。

1. **一次要件** — 公式ページとフォーム画面（締切・資格・動画URL公開条件・字数）を読む。国別締切がズレることがある → 英語/日本語ページとフォームを突合
2. **置き場** — 文案は `DB_Action` の該当タスク本文＋必要なら `/opt/data/tmp/…-prep-YYYYMMDD.md`。提出は **送信ゲート**（`toya-outbound-send-gate`）
3. **動画台本（60秒）**  
   - 日本語自然発話の目安: **約220–280字 / 60秒**（余裕を見て 300字超は削る）  
   - 製品固有名（Hermes 等）は出さず「エージェント／手順化／秘書」で書く  
   - 設問が「キャンパス」なら **学内・ピア伴走**を本線。Notion Fukuoka は「事実が厚い肉付け」として頭の中 or 1文まで（字面どおりの審査に備える）  
   - URL: 限定公開 / Drive「リンクを知っている全員」。提出前にシークレットで開けること
4. **テキスト設問の軸（とーや向け・実測済みテーマ）**  
   - 若者の課題: 情報過多→判断軸が育ちにくい ＋ **AI解答の鵜呑み** ＋ 作って見せて直す場  
   - 考えの変化: **「ちょっともの知りな友人」→「自分専用のAI秘書」**（180度）。任せて・確かめて・残す。最後の取捨選択は自分  
   - 任意「OpenAIに伝えたいこと」: 短く1メッセージ。**地方キャンパス（福岡/FIT）＋デモより型＋確かめ文化**が固有。感謝だけ／一般論は弱い
5. **反復** — ユーザーが全文を貼り直したらそれを正本にし、字数だけ／指定テーマの加筆だけに応じる。勝手に別テーマへ戻さない

詳細メモ: `references/student-program-essays.md`
## 個人情報・安全

- 履歴書xlsxに電話・住所が入っている。チャットにフル住所・電話を不要にエコーしない
- 秘密・学籍番号は出さない

## 外部の応募・問い合わせ送信

店舗・採用の **Web 問い合わせ／応募フォーム** やメール送信は、文面・xlsx 作成とは別ステップ。  
**とーやの明示「送信して／送信許可」等があるまで submit/send しない**（「書いて」「入れて」「動かして」は不可）。  
手順の正本: skill `toya-outbound-send-gate`。日程が絡むなら先に `toya-schedule-coordination`。

## ピットフォール

1. 長文・広報口調・ガクチカの盛り（ユーザーが一発で却下する）
2. 字数を目測する（必ず Python）
3. 文だけ出して xlsx を忘れる（「お任せ」＝Driveまで）— **学生プログラムは xlsx 不要**、Action/tmp に正本
4. openpyxl で写真消失を確認せず upload
5. Indeed 本文なしで想像の業務内容を書く
6. AI表記を「ChatGPT使えます」止まり／逆にプロダクト名を履歴書・動画に並べる
7. 応募・問い合わせフォームを、文面作成依頼だけで送信してしまう
8. 「500字近い」依頼なのに半分程度で止める
9. 動画台本を読み上げ1分超（300字超）にする／キャンパス設問なのに学外コミュニティだけを主語にする
10. 任意コメントを一般的なAI賛美だけにする（地方・伴走・確かめの固有軸を落とす）
